# 規格文件審閱者提示模板

使用此模板派發規格文件審閱者子代理。

**目的：** 驗證規格是否完整、一致，並已準備好進行實作規劃。

**派發時機：** 規格文件已寫入 docs/superpowers/specs/ 之後

```
Task tool (general-purpose):
  description: "Review spec document"
  prompt: |
    你是一個規格文件審閱者。驗證此規格是否完整且已準備好進行規劃。

    **要審閱的規格：** [SPEC_FILE_PATH]

    ## 檢查項目

    | 類別 | 檢查重點 |
    |----------|------------------|
    | 完整性 | TODO、佔位符、「TBD」、不完整的區塊 |
    | 一致性 | 內部矛盾、相互衝突的需求 |
    | 清晰度 | 模糊到足以讓人構建出錯誤內容的需求 |
    | 範圍 | 足夠專注於單一計畫——不跨越多個獨立子系統 |
    | YAGNI | 未被請求的功能、過度設計 |

    ## 校準標準

    **只標記會在實作規劃期間造成真實問題的議題。**
    缺少一個區塊、一個矛盾，或一個可以被解釋為兩種不同方式的需求——
    這些才是議題。輕微的措辭改善、風格偏好，以及「某些區塊比其他區塊
    細節少」都不是議題。

    除非存在會導致計畫有缺陷的嚴重缺口，否則應批准。

    ## 輸出格式

    ## 規格審閱

    **狀態：** 已批准 | 發現議題

    **議題（若有）：**
    - [區塊 X]：[具體議題] - [為何對規劃有影響]

    **建議（僅供參考，不阻擋批准）：**
    - [改善建議]
```

**審閱者回傳：** 狀態、議題（若有）、建議
