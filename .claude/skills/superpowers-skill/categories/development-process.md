# Development Process

## Purpose

Use this file to route core development-workflow requests inside the superpowers catalog.

## Trigger Conditions

- The task involves feature planning, TDD, debugging, or completion verification.

## Skill Mapping

- If the user needs design clarification before starting feature work, read [brainstorming](../skills/brainstorming/SKILL.md).
- If the user needs to convert an approved spec into a step-by-step implementation plan, read [writing-plans](../skills/writing-plans/SKILL.md).
- If the user needs to execute a plan in a new session, read [executing-plans](../skills/executing-plans/SKILL.md).
- If the user is writing a feature or bug fix and must start with failing tests, read [test-driven-development](../skills/test-driven-development/SKILL.md).
- If the user is facing a bug, test failure, or unexpected behavior, read [systematic-debugging](../skills/systematic-debugging/SKILL.md).
- If the user is about to claim completion or prepare for commit or PR, read [verification-before-completion](../skills/verification-before-completion/SKILL.md).

## Notes

- `brainstorming` has a hard gate: do not enter implementation before the design is clarified.
- `test-driven-development` has an Iron Law: no product code before a failing test.
- `systematic-debugging` has an Iron Law: do not propose a fix before root-cause investigation is complete.
- `verification-before-completion` has an Iron Law: verification only counts if the command is run in the current message.
