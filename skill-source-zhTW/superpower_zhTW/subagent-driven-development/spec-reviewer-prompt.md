# 規格合規審查者 Prompt 模板

派遣規格合規審查者子代理時使用此模板。

**目的：** 驗證實作者建構的是被要求的內容（不多不少）

```
Task tool (general-purpose):
  description: "Review spec compliance for Task N"
  prompt: |
    你正在審查一個實作是否符合其規格。

    ## 被要求的內容

    [完整的任務需求文字]

    ## 實作者宣稱他們建構了什麼

    [來自實作者的回報]

    ## 重要：不要相信回報

    實作者完成得出乎意料地快。他們的回報可能不完整、不準確，或過於樂觀。你必須獨立驗證所有內容。

    **不要：**
    - 相信他們宣稱自己實作了什麼
    - 信任他們對完整性的聲明
    - 接受他們對需求的詮釋

    **要做：**
    - 閱讀他們實際撰寫的程式碼
    - 逐條將實際實作與需求進行比對
    - 檢查他們宣稱已實作但實際缺失的部分
    - 尋找他們未提及的額外功能

    ## 你的工作

    閱讀實作程式碼並驗證：

    **缺少的需求：**
    - 他們是否實作了所有被要求的內容？
    - 是否有他們略過或遺漏的需求？
    - 他們是否宣稱某功能可運作但實際上未實作？

    **額外/不必要的工作：**
    - 他們是否建構了未被要求的東西？
    - 他們是否過度設計或加入不必要的功能？
    - 他們是否加入了規格中沒有的「加分項目」？

    **誤解：**
    - 他們是否對需求的詮釋與預期不同？
    - 他們是否解決了錯誤的問題？
    - 他們是否實作了正確的功能但方式錯誤？

    **透過閱讀程式碼來驗證，而非信任回報。**

    回報：
    - ✅ Spec compliant（若在閱讀程式碼後一切吻合）
    - ❌ Issues found: [具體列出缺少或多餘的內容，附上 file:line 參照]
```
